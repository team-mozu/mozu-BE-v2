# Architecture — mozu-BE-v2

Backend for Mozu (모의 주식 투자 교육 플랫폼). Kotlin/Spring Boot with a **hexagonal (ports & adapters)** layout.

## 1. Layer Map

```
adapter/in/*       Web (REST + SSE) — Spring controllers, request/response DTOs
   │
   ▼ (calls)
application/port/in/*    Use-case interfaces (the inbound boundary)
   │
   ▼ implemented by
application/service/*    Use-case implementations (Spring @Service)
   │
   ▼ (calls)
application/port/out/*   Outbound interfaces (persistence, messaging, S3)
   │
   ▼ implemented by
adapter/out/*      JPA repositories, Redis, S3, SseEmitter store
```

Cross-cutting:

- `domain/*/model` — pure Kotlin domain models, no Spring imports
- `global/config/` — Spring config (security, redis, querydsl, S3)
- `global/security/{jwt,auth}` — JWT verification + principal resolution
- `global/scheduler/` — scheduled jobs (SSE heartbeat / cleanup)
- `global/error/` + `global/exception/` — handler chain, structured error responses
- `global/document/` — Swagger / SpringDoc interfaces

## 2. Package by Domain

Each business domain has a slice through all layers. Example for `lesson`:

```
adapter/in/lesson/         LessonWebAdapter, dto/{request,response}, NextLessonEventDTO, StartLessonEventDTO
adapter/out/lesson/        JPA entities, repositories, persistence adapters, mappers
application/port/in/lesson/    use-case interfaces (one per service)
application/service/lesson/    use-case implementations (split per action: Create, Start, StartInvestment, Next, End, Update, Delete, ChangeStar, multiple Query*)
application/exception/lesson/  domain-aware exceptions surfaced to the API
domain/lesson/             model + exception
```

Same shape for `article`, `item`, `organ`, `team`, `sse`.

## 3. Persistence

- MySQL via JPA (entities in `adapter/out/*/entity/`) + QueryDSL for dynamic queries (Q-classes generated by KAPT).
- Migrations: `src/main/resources/db/migration/V{n}__*.sql` (Flyway, baseline 1, auto on startup).
- Redis (Lettuce) for cache / coordination (configured in `global/config/redis/`).
- S3 for image uploads (item logos, article images) via `adapter/out/s3/`.

## 4. Web Surface (high level)

REST controllers under `adapter/in/`:

- `auth/` — login, token reissue
- `organ/` — institution / admin account
- `lesson/` — lesson CRUD, start/next/end, queries, lesson-organ SSE connect
- `item/` — stock CRUD
- `article/` — news CRUD
- `team/` — student participation, team SSE connect, team queries
- `sse/SseWebAdapter` — `/sse/subscribe?clientId=...` (generic / legacy)

Auth: JWT bearer (filter chain in `global/security/jwt/`). CORS in `global/config/security/SecurityConfig.kt` — explicit origins for `admin.localhost`, `student.localhost`, `mozu-admin.vercel.app`, `mozu-student.vercel.app`, plus private-network patterns (`192.168.*`, `10.*`, `172.16.*`).

## 5. SSE Substrate

Three logical channels, one storage:

| Channel | Endpoint | Connect service | Audience |
|---------|----------|-----------------|----------|
| Lesson-Organ | `GET /lesson/sse/{lessonId}` (in `LessonWebAdapter`) | `LessonOrganSSEService` | One admin connection per lesson |
| Team | `GET /team/sse` | `ConnectTeamSSEService` | One per student / team |
| Generic | `GET /sse/subscribe?clientId=...` | `SubscribeSseService` | Legacy |

Publishers: `PublishToSseService` (point-to-point) and `PublishToAllSseService` (broadcast).
Emitter store: `adapter/out/sse/persistence/SseEmitterRepository.kt` — in-memory map keyed by domain-specific id (e.g. `lesson-organ-sse:{lessonId}:{organId}`).

Implication: **the BE assumes a single instance.** Horizontal scale-out would need Redis pub/sub or sticky sessions.

See `./SSE_API_SPECIFICATION.md` for the wire-level contract (event names, payload schemas) and `./system-design.md` for the runtime sequence and failure modes.

## 6. Lesson Lifecycle (state machine)

```
CREATED ──Start──▶ READY ──StartInvestment──▶ ROUND_n ──Next──▶ ROUND_n+1 ──...──▶ ENDED
                                                  └─End──────────────────────────────▶ ENDED
```

Each transition is its own service: `CreateLessonService`, `StartLessonService`, `StartLessonInvestmentService`, `NextLessonService`, `EndLessonService`. SSE events fan out from these services to the lesson-organ and team channels.

Event names (`domain/sse/model/SseEventType.kt`):
- `START_LESSON_EVENT` → wire name `CLASS_START`
- `NEXT_LESSON_EVENT` → wire name `CLASS_NEXT_INV_START`
- (more in SSE_API_SPECIFICATION.md)

## 7. Build / Run

- Gradle KTS, Kotlin 1.9, JVM 17. Plugins: `kotlin("jvm")`, `kotlin("spring")`, `kotlin("kapt")`, `kotlin-jpa`, Spring Boot, ktlint.
- KAPT generates QueryDSL Q-classes and MapStruct mappers.
- Local stack: `docker-compose.yml` (mysql + redis + prebuilt server image) with `docker-compose.override.yml` remapping MySQL host port to 3307.

## 8. Cross-cutting Conventions

- Inbound DTOs convert via `of(...)` / `from(...)` factory methods on the DTO classes (recent refactor — do not push conversion logic back into mappers).
- Domain models never import Spring. Use `application/service/` to translate between adapter DTOs and domain models.
- All exceptions extend a base type in `global/error/exception/` so the global handler can format consistent error payloads.
- SSE emitter cleanup uses lifecycle callbacks (`onCompletion`, `onTimeout`, `onError`) inside the persistence adapter.

## 9. Lesson + Monitoring Data Model (as-is)

오늘 운영에서 드러난 문제들을 근거로 모델/스키마를 정리.

### 9.1 테이블 한 줄 요약

| 테이블 | PK | 역할 | 주요 FK | 비고 |
|---|---|---|---|---|
| `tbl_organ` | UUID(binary 16) | 기관 = admin 계정 | — | unique `organ_code` |
| `tbl_lesson` | UUID | 수업 1개 = 한 운영 단위 | `organ_id` | `lesson_num` CHAR(4) unique, `cur_inv_round`/`max_inv_round`, `is_in_progress`/`is_deleted`/`is_starred` |
| `tbl_item` | INT AUTO_INC ≥1000 | 종목(기업) 마스터 | `organ_id` | `capital`/`debt`/`profit`/... 재무 컬럼 직접 컬럼화 |
| `tbl_lesson_item` | (item_id, lesson_id) | 수업별 종목 가격표 | item, lesson | `end_price`/`round1price..round5price` — V6 rename |
| `tbl_article` | UUID | 기사 마스터 | `organ_id` | 본문 VARCHAR(10000) |
| `tbl_lesson_article` | (article_id, lesson_id) | 수업 N차 기사 매핑 | article, lesson | `investment_round` |
| `tbl_team` | UUID | 학생 팀(참여 단위) | `lesson_id` | `lesson_num` CHAR(4) NOT NULL (V8), `is_investment_in_progress`, `cash_money`/`total_money`/`valuation_money`. unique `(team_name, lesson_num, lesson_id)` (V8) |
| `tbl_order_item` | UUID | 매수/매도 주문 1건 | item, team | `order_type` enum(BUY,SELL), `inv_count`, `item_price`/`order_count`/`total_money` |
| `tbl_stock` | UUID | 팀이 보유 중인 주식 포지션 1건 | item, team | `avg_purchase_price`/`quantity`/`buy_money`/`val_profit`/`profit_num` |

### 9.2 의미적 관계도

```
tbl_organ 1 ───< tbl_lesson 1 ───< tbl_team 1 ───< tbl_order_item
                       │                    └───< tbl_stock
                       ├───< tbl_lesson_item >─── tbl_item ─── (organ owned)
                       └───< tbl_lesson_article >─── tbl_article ─── (organ owned)
```

### 9.3 알려진 모델·스키마 부채

1. **`tbl_lesson_item`의 round 가격이 컬럼 5개 + end_price**
   `round1price` ~ `round5price` 컬럼. round 추가 시 schema migration 필요. round-as-row 구조(`tbl_lesson_item_round (item_id, lesson_id, round, price)`)가 자연스러움.

2. **`lesson.cur_inv_round` 단일 정수로 진행 상태 표현**
   "준비 단계"(투자 시작 전)인지 "round N 진행 중"인지 "ended"인지를 `cur_inv_round=0` + `is_in_progress` + `is_deleted` 3개 boolean으로 표현. 상태 머신을 enum 단일 컬럼(`LessonStatus` = `CREATED/READY/IN_ROUND/ENDED/DELETED`)으로 압축이 깔끔.

3. **`tbl_team`의 자산 컬럼이 3개로 중복**
   `cash_money` + `total_money` + `valuation_money`. 산식: `total_money = cash_money + valuation_money` (불변식). DB에 셋 다 저장 + 매 거래마다 같이 update → 동기화 깨질 위험. 둘 중 한쪽은 derived(view 또는 응답 시 계산)로 줄이는 게 안전.

4. **`tbl_team.team_name`의 도메인 모델 nullable 불일치**
   TeamJpaEntity는 `var teamName: String?` (`@Column(nullable = false)` + nullable 변수), Team 도메인은 `String` non-null. mapper.toModel에서 강제 변환. 도메인 모델 일관성 깨짐.

5. **`tbl_team`의 `lesson_id` + `lesson_num` 중복**
   `lesson_num`은 `tbl_lesson` 안에 이미 unique. team에 또 들고 있는 이유 = JWT principal에 lessonNum만 박혀있어서 lookup 우회용. 정상화하면 join 한 번 더 들지만 데이터 정합성 ↑.

6. **`Team.createdAt` non-null vs entity nullable**
   오늘 운영에서 터졌던 IAE. `@EnableJpaAuditing` 추가로 임시 해결됐으나 `@CreatedDate` 컬럼은 flush 전엔 null이므로 mapper.toModel가 save 직후 호출되면 위험. **모든 도메인의 created/updated는 nullable로 통일** 권장.

7. **`tbl_order_item.inv_count`의 의미 불명**
   주문 시점의 차수(`inv_count`)인지 누적 카운트인지. column명만으론 모호. 명확한 이름(`order_round`)이 나음.

8. **monitoring 데이터의 source of truth가 SSE에만 있음**
   admin 화면의 팀별 종료 상태는 zustand `teamInfoMap.trade[]` 길이로 판정 — SSE의 `TEAM_INV_END`만이 채움. SSE 손실 시 admin은 영영 못 따라잡음. **DB의 `tbl_team.is_investment_in_progress` + `tbl_order_item`의 round별 row가 진짜 truth**. 폴링 endpoint (`GET /lesson/{id}/teams`, 추가됨) 또는 `GET /lesson/{id}/round-status`로 정규화 필요.

9. **`/team/sse`의 emitter pool 키 `team-sse:{teamId}` + admin `lesson-organ-sse:{lessonId}:{organId}` 동일 ConcurrentHashMap**
   다른 도메인 키가 하나의 in-memory map을 공유. clientId 스푸핑 가능했던 `/sse/subscribe` 라우트는 제거됐지만 key collision 방지는 prefix에만 의존.

10. **SSE 이벤트 store(Redis Streams)와 emitter pool 사이 atomic 동기화 없음**
    `publishTo`가 `eventStore.save` 후 `emitter.send`. 사이에 emitter 없어지면(끊김 race) save는 됐지만 send 못 함 → admin 재연결 시 `Last-Event-ID`로만 복구 가능. 우리가 `LessonOrganSSEService.subscribeWithRecovery` 추가로 복구 길은 만들었음.

### 9.4 리팩토링 제안 (단계별)

**Phase 1 — 도메인 모델 정합성 (BE 내부, 운영 영향 0)**
- 모든 entity의 `created_at`/`updated_at`에 대응하는 도메인 모델 필드를 `LocalDateTime?`로 통일
- `TeamJpaEntity.teamName`을 `String` non-null로 통일
- `tbl_lesson_team.lesson_num` 컬럼은 유지하되 read-only로 마킹, write는 `tbl_lesson` 통해서만

**Phase 2 — Lesson 상태 머신 정규화**
- `LessonStatus` enum 컬럼 추가 (`CREATED/READY/IN_ROUND/ENDED/DELETED`)
- 기존 boolean 3개는 view 또는 응답 시 derive
- 마이그레이션: V9 새 컬럼 + backfill SQL

**Phase 3 — Round 가격 정규화**
- `tbl_lesson_item_round (item_id, lesson_id, round, price)` 신설
- 기존 `round1price..round5price` → row로 backfill
- max_inv_round 제약 풀려 N차 수업 가능

**Phase 4 — Monitoring 데이터 source 정리**
- `GET /lesson/{id}/round-status` 신설: 각 팀의 각 round 별 (총자산, 평가손익, 수익률) 반환
- admin FE는 이 응답을 truth로 쓰고 SSE는 알림 + 즉시 갱신 hint
- `tbl_round_snapshot (lesson_id, team_id, round, total_money, valuation_money, cash_money, profit_num, created_at)` 신설 가능 (history)

**Phase 5 — SSE 신뢰성**
- `LessonOrganSSEService`의 lastEventId 복구 (이미 적용됨)
- 인프라 ingress timeout 조정 요청 (학교 PaaS)
- BE 측 ping을 comment에서 실제 event(`name=heartbeat`)로 변경
- multi-instance 운영을 위한 Redis pub/sub fan-out (선택)

각 Phase는 독립 배포 가능하고 이전 Phase 없이도 fix됨. Phase 4가 운영 안정성에 가장 영향 큼.
